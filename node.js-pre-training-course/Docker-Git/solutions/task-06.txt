Interactive rebase to squash
git rebase -i HEAD~5

REBASE VS MERGE: WHEN TO USE

USE REBASE WHEN:
- Working on local feature branch not yet pushed to remote
- Want clean, linear commit history without merge commits
- Need to clean up commits before creating pull request (squash typos, reorder)
- Working alone or on small team with clear communication
- Want to keep feature branch up to date with main without merge commits
- Need to incorporate latest changes from main into feature branch

USE MERGE WHEN:
- Working on public/shared branch that others depend on
- Multiple developers working on the same feature branch
- Need to preserve complete history and context of when branches diverged
- Want to see explicit integration points in history
- Compliance/audit requirements need full historical record
- Working on long-lived feature branches
- Want safer approach (doesn't rewrite history)

KEY DIFFERENCES:
REBASE:
- Rewrites commit history
- Creates linear, cleaner timeline
- Moves entire branch to new base
- Can cause issues if branch is already pushed/shared
- Better for local cleanup before sharing work

MERGE:
- Preserves complete history
- Creates merge commits showing integration points
- Shows true branching structure
- Safe for public/shared branches
- Better for collaborative work and preserving context
